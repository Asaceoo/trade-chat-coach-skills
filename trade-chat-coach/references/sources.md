## 0 可靠性分级约定

- **A** = 有可追溯的原始研究/一手出处（原始论文、出版方书目记录、机构官方发布），可当事实引用。
- **B** = 机构/厂商/作者自报数据（可能带营销目的），引用时注明"机构自报"。
- **C** = 网络流传、本技能调研期间查不到原始出处——**不得当事实引用**，只能当行业常识提及。
- 本文件所收录的来源按此标注。**凡是标 C 的，说话时一律回避具体数字。**

## 5 明确不采用/禁引用的说法（防翻车清单）

1. "5 次拒绝 8 次跟进"类跟进次数民俗数字——查无出处。
2. "64% 销售不主动要成交"——培训厂商数据，且常被错误归因。
3. "35,000 次 SPIN 研究访谈"——未核到一手出处。
4. "客户 7 次不回就该放弃"——无出处；本技能用"三次不同由头 + 收尾信"作为可操作标准。
5. 任何没有编号可查的"XX 协会认证""XX 权威背书"——本技能红线禁止编造背书。

## 7 B站语料观察（口径：**yt-dlp 通道 51 条**去重视频元数据，2026-10-07 采集）

原始语料见 `research\bilibili_corpus.md`（51 条口径）。几条对话术库有用的观察：

1. **中文门店/零售话术市场高度行业化**：瓷砖、珠宝、美业、产后修复、4S 店延保各有成套"行业话术"——这类话术强在场景匹配，弱在底层结构。我们的处理方式是：**结构用方法论（SPIN/异议模型），场景由用户提供**，比背行业模板更抗变化。
2. **"销售高情商训练营"类内容常见"客户性格/微信头像分析"**——把头像、朋友圈当客户分型依据，属于**民俗心理（C 级）**，无实证支撑，本技能不采用；真实的分层依据是行为成本（给了什么规格/付了什么成本），见 signals.md。
3. **外贸类视频以小知识点为主**（询盘英语、第一次打电话、跟进节奏），验证了"外贸业务员的真实痛点是判断+跟进"，与本技能的定位一致。
4. **播放量整体不高**（多数 <2 万），说明中文平台的高质量外贸话术内容稀缺——这也意味着"结构化话术库"的差异化价值。

  - `--ids "[200]"`（文档写 `--id`，实测报 `key 'id' is not exist`；实现用 `ids` 复数 + **list 格式**）；
  - `--user_data 1` / `--headless 0`（**用 `1/0`，官方口径**；写 `true/false` 报 `Cannot convert false to type bool`，因 commandline_config 用 Python eval 解析）；
  - **`--user_folder` 只在 `--user_data=1` 时生效**（官方明确），此前实测用 `--user_data False` 导致 profile 被忽略；
  - `--read_type local` 读 **`execution_instances/{id}.json`**（官方确认，非 `tasks/`）；
  - graph 的 `sequence` 存**数组下标**非节点 id（写 id 报 `list index out of range`）。
  - 环境坑：中文安装路径致 chromedriver 乱码 → 整目录复制到**纯 ASCII 路径**；`config.json` 的 `absolute_user_data_folder` 默认指向作者开发机路径（不存在）需改；提取含 ¥ 符号时控制台 GBK 打印崩溃（`PYTHONIOENCODING=utf-8`）。

  - ⚠️ **知乎需登录态**：任务 203 无登录跑出的 50KB 全是**登录墙文本**（"打开知乎App 扫码登录"），正文 0 字节。**解决方案**：用 EasySpider 捆绑 Chrome（131）创建独立 profile，人工扫码登录知乎一次，之后以 `--user_data 1 --user_folder <该profile>` 复用登录态（注意：Chrome 154 的 CDP profile 与捆绑 Chrome 131 **版本不兼容**，不能直接复用）。
  - **工作流定位**：EasySpider = 渲染型平台（微信读书 SPA / 知乎 SPA）的内容抓取；配套 OCR 管线（小红书图集）与 requests 管线（当当 SSR）分工使用。

**方法结论**：小红书/知乎类平台的高赞话术增量抓取，MediaCrawler(CDP) + OCR 是当前最稳管线；微信读书评分核实走浏览器内 fetch API 比网页抽取快且稳；当当这类老派 SSR 电商站 requests+GBK 编码直抓即可，无需浏览器；WebRPA 适合定时编排场景，以及需要 GUI 级浏览器操作的常规化抓取，但依赖功能包完整。
