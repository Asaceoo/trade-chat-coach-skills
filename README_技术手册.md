## 一、架构

```
SKILL.md（主文件，≤500 行）
  ├─ 五步流程：重建事实 → 四必答题 → 判定 → 输出 → 跟进
  ├─ 三模式：实战 / 批量 / 实时（+ 单点咨询）
  └─ 路由表：28 个 references 的唯一入口 + 仲裁规则
references/（28 个 .md）
  ├─ 判定层：signals / framework / zh-playbook（≤2 个，Step 1-2）
  ├─ 推进层：6 份可抄 phrasebank + 1 份引证型金句库（≤1 个，判定之后）
  └─ 语料层：B站/知乎/网页/读书 四源 + data-bank 唯一数字出处
evals/（11 用例 + 8 夹具，自述结论 verification: self-reported）
```

**读取预算**：全程 ≤3 个文件（硬上限）。判定层 2 → 推进层 1；破例读第 3 个（如补信任度刻度）则推进层归零——预算可结算、不可静默超支。

**混合型文件纪律**：zh-playbook / domestic-corpus 等同时含"信号"与"话术"——允许先读，**判定完成前禁止取用其中话术部分**。

## 三、发布流水线（release_pipeline_v2.py，8 步）

```
[pre]  快照 3 文件（失败回滚）→ 手册预同步（防 F9 自锁）→ 语义版本序清理历史 zip（防 F8 自锁）
[0]    44 项清单校验
[1]    版本递增 semver（patch/minor/major）
[2]    两手册版本串同步 + 技术手册 §7.6 自动补行（表格边界 + 只看表格行判重）
[3]    stage 构造 + 官方校验
[4]    打包 .skill + zip → [4b] verify_artifact 产物契约校验
[5]    CHANGELOG 插段（按分隔符拆 bullet，杜绝空壳段）
[6]    源码/手册/.skill 同步发布仓库 + 清理历史 zip（保留最新 1 个）
[7]    git commit + push（非交互凭据：GCM_INTERACTIVE=never）
[8]    GitHub Release + 4 资产上传（资产名必须纯 ASCII）+ gh_api 网络重试（4 次指数退避）
```

**自锁教训**：凡是「校验在 [0]、修复在后面」的项都会死锁——校验失败即中止，永远走不到修复。所有清理/同步必须前置到 [pre]。已踩两次（F8 zip、F9 手册）。

## 五、合规边界

技能显式拒绝：演戏逼单（假库存/假稀缺）、编造资质与客户案例、消费信贷式催收施压、以礼品/宴请或回扣换取采购决策。
回扣场景给的是**法律定性 + 微信留痕拒绝话术 + 明面替代方案**，不是规避建议。所有判断输出置信度——**是概率，不是判决**。

## 六、数据口径与出处

- 数字唯一出处：`data-bank.md`（A/B/C 分级 + 禁引用清单 + 常见误归因如梅拉宾 55/38/7）
- 划线金句：读者行为数据 ≠ 内容正确性证明，引用必须注明**划线人数 + 书名**
- 「93% 砍价」类机构自报数字为实证级 B，引用须注明机构口径
